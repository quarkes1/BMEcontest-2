## 2. 量化结果

### L1 守门员（folds 0-3 训练，验证集）
- 唤醒灵敏度 **0.985**、特异度 0.179、唤醒后正占比 6.8%、模型 11KB
- 定位：高召回粗筛（宁多勿漏），L3 只处理唤醒窗口；阈值可上调换取过滤率

### L2 场景门控（正样本验证）
- 场景准确率 **0.629**、高置信占比 73.6%（低置信走 IMU 保守分支）
- 弱于预期：7 维倾角特征区分惯用/非惯用场景能力有限，W3 补充姿态角变化率等特征

### L3a 两折（W2 主交付）

|---|---|---|---|---|
| 0 | 0.053 | 0.068 | 0.1 | 20 |
| 1 | **0.245** | 0.146 | 0.6 | 25 |

对照：W1 LightGBM 基线 5 折均值 F1 = 0.106（同一评估口径）→ L3a fold 1 已超基线 2.3×。

### 关键发现：逐餐极化（scripts/diagnose_l3a.py）
- 逐餐"餐内窗口通过率"两极分化：~1/3 的餐通过率 0.9+（如 HNU21031 0.93/0.92），其余 0.00-0.10（如 HNU21011 三餐全不可见）
- 结论：**IMU 单分支天然无法覆盖全部餐**（受食物/餐具/实际用手影响，部分受试者进食时腕部几乎无动作）。这正是 spec 设计 L3b（PPG 生理分支）+ 动态可靠性加权融合的动机，W3 落地
- 跨折差异（0.053 vs 0.245）同源于受试者可检测性差异

## 3. 关键工程教训（已修复并归档）

1. **Windows spawn 数据管线不可靠**（worker 满载、主进程死等、GPU 空转）→ 负样本 3:1 抽样后全量入内存（~10GB）+ num_workers=0，epoch 27s
2. **压缩 npz 随机访问灾难**（每 batch 解压上百文件，实测 200h/epoch）→ 缓存改不压缩 + 顺序访问
3. **阈值扫描区间必须覆盖低概率区**（不平衡训练下 0.1-0.25 才是工作区，0.3-0.7 全错区）
4. **事件级 IoU>0.25 需要长连续预测段** → 概率序列 31s 中值平滑入正后处理（单会话实验 F1 0.222→0.286）
5. **跨折验证缓存污染** → 每折构建前清空目录
6. 评估真值口径：餐标签 1 餐 1 事件（不用正窗口重建）

## 4. W3 提升路径（按预期收益排序）

1. **L3b 生理专家**（PPG 44 通道 GRU，~150K 参数）——覆盖 IMU 不可见餐
2. **动态可靠性加权融合**（alpha=MLP(PPG SNR, 灌注指数, IMU 活动度)）——自动按餐分配两分支权重
3. **L4 HMM 状态解码**（2 态 Viterbi，替代中值平滑的正式方案）
4. L3a 强化：更多轮训练+dropout 正则（pos_acc 0.83 vs 验证通过率 0.30 显示过拟合）
5. L2 特征增强（姿态角变化率分位数、陀螺活动度组合）
