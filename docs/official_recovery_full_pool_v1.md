# FULL-POOL-V1：训练侧候选覆盖修复

2026-10-20。自主探索计划内的新窄假设；不是正式发布或独立泛化结论。

## 新证据

固定完整GT/分数的T24诊断：160餐中72TP、56无IoU>.25的raw候选、32有候选但评分不足；63个旧eligible外餐中52无候选。无候选不是必然无原始动作。
原outer-train加载器把meal_train与最多150个no_meal_train会话作为candidate_train，内层health沿用这份候选子集。T24仅227会话，而全量已有缓存为696宏窗/702微窗会话。56个无候选餐中，31个在完整缓存有>=80%覆盖、但旧候选池不足80%，宏/微两个尺度均如此；其中宏窗25个、微窗24个原池零覆盖。此处是缓存支持，不是有效IMU的重新检测。

因此前两项对照仅证明抽样候选池内没有稳定收益，不足以否定全会话范围的召回修复。研究首先修复内层候选范围，而不是用它挑一个更大的模型。

## 固定对照

仍为既有T24三个16train/8health、每分区三折policy OOF及四折窗口crossfit。A为EVENT-COVERAGE-V1 confirmed的full臂（完整事件监督、抽样候选池），冻结其候选、分数、policy，作为同口径baseline F1=.5584905660；B使用全量T24宏/微缓存候选窗口，完整事件监督/策略目标不变。

只扩大candidate_train，不改变window_train/micro_window_train的任何样本、标签、权重、特征、seed或估计器。窗口模型在每个相同训练分区重新fit；同一次full生产器得到B候选。A已选会话上的原始窗口特征必须逐行与完整缓存相等，A候选的事件/两路支持必须是B对应session的精确子集，否则中止，不静默比较。

每分区micro阈值沿用A同一训练分区的冻结阈值，不允许因候选池扩大而另调生产器。检查源祖先图排除score/health/V7/outer；B新增verifier和policy只在当前train主体拟合。B固定116D、LR C=.1和LGBM各.5融合；不增加表示、不改NMS范围、不拼接跨文件事件、不使用失败的窗口重标B。

数据来自五份现有val NPZ的去重联合，仅选T24。允许读取共享NPZ字节，但任何非T24窗口在fit、候选生成、选策略前必须裁掉。不能声称未物理读取其他主体字节。补充完整session主体映射/权威索引边界；无候选GT保留完整160餐分母。

三个B策略均由独立嵌套policy OOF选定并写盘后才开始B health refit。两臂评价同一完整GT、严格IoU>0.25，A计数必须回放74TP/31FP/86FN，不与153餐发布F1或之前day-budget的另一baseline混用。

## 工程门与资源

固定pooled事件F1 B-A>=.01、至少2/3折提高；必须报告TP/FP/FN、逐人改善恶化及两臂raw候选可达性。T24反复开发，不称独立测试；即使通过也须先做更广训练侧验证与官方接口验证，不直接更新dist。

CPU4数值线程；预计120次旧窗口模型fit和24次B verifier fit，A不重复fit。墙钟<=2小时，证据<=64MiB、可用磁盘>=10GiB。仅内存使用完整窗口特征，不写新特征缓存/模型权重，不读原始IMU向量。保存源SHA、祖先图和配对账本，模型/release/EXE前后保护不变。失败标INCOMPLETE，禁止挑完成折。
