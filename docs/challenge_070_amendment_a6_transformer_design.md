# Amendment A6 — 双任务层级 Transformer 与 FD 序列扩充设计

日期：2026-10-12。状态：本书面设计已获用户审阅通过；T0/T1实施计划已编写，待审阅，尚未实现或训练。

下一步：[T0/T1实施计划](superpowers/plans/2026-10-12-a6-transformer-t0-t1-plan.md)。

## 1. 目标与当前边界

目标是正式、受试者隔离的事件 F1 达到 0.70+，同时解决两个问题：真实餐段没有可用候选，以及候选存在但无法与 eating-like FP 区分。不能把候选 AP、源域动作 AP 或开发集 F1 当成正式成绩。

正式版本仍为 `160afaf81debf1ee`：F1 **0.6514285714**，TP/FP/FN = **114/83/39**。本轮不改变 release、dist、前端接口或旧实验结论。

A5 的代码与审查修复保留；其全仓回归在中途停止，没有完整通过记录，也没有生成 manifest 或开始三臂训练。遵照用户“先别启动”的要求，A5 暂停，不自动恢复，不能记为算法失败。

本设计批准后先写实施计划，锁定可执行配置、预算与评价协议，再开始实现。本文不是立即运行实验的指令。

## 2. 证据与架构选择

- 冻结 FD 表示曾在 T24 开发对照中从 .721311 到 .741935，但仅 1/3 折改善；S11 适配减少 FP，却没有稳定胜过冻结 FD。这是表示可能有用的信号，不是独立泛化确认。
- 之前的小型时序读出、更多源域训练以及某个外部预训练桥接没有通过各自 gate；不能据此断言所有 Transformer 无效，也不能期待换 attention 就自动提升。
- 候选控制诊断说明单纯松开 cap/admission 成本高，很多恢复的真实候选仍被后级拒绝。只增加 proposal 不能解决全部问题。

不选择直接对全天原始采样点做全局 attention：算力和样本复杂度都高，也难归因。不只做候选级 Transformer：它永远救不回没有候选的餐段。

选择**局部动作编码 + 连续时间 Transformer + 定位/复核两条路径**。先分开验证，再决定是否联合微调。

## 3. FD 审计与使用合同

本地依据：`FDdatasets/doi-10.48804-CN8VBB/v1.0/00_ReadMe.txt`。2026-10-12 只读检查了 FD-I、FD-II 和 MO 的 zip 成员，均只有左右手 X/Y pickle，没有独立餐段边界文件。没有解压 MO，也没有为写设计加载多 GB 的原始数组。

| 数据 | 已知标注与覆盖 | 本设计用途 | 禁止推断 |
| --- | --- | --- | --- |
| FD-I | 34 人、251.70h；连续双腕 ACC/GYRO，64Hz；逐点 0/1/2 手势标签 | 沿用已冻结的源域编码器；后续独立验证连续序列手势辅助训练 | 不能把手势 0 当 non-meal，不能把相邻手势自动连成真实餐段 |
| FD-II | 27 人、261.68h；只标注餐中手势，说明书提及餐边界但本地未找到独立文件 | 首版保留作源域审计/迁移检查，不用于参数选择；若后续启用训练须另行登记 | 餐外 0 不等于可靠负例；不得同时用于训练和独立测试 |
| MO | 46 人的 meal-only 数据；文档说明与 FD 无受试者重叠 | 后续可单独注册为动作监督扩充，不在首版静默加入 | 无全天负例，不能训练 meal/non-meal 全天判别 |

动作标签：1=eating gesture、2=drinking gesture、0=other。餐段内两个 bite 之间通常也可以是 0，因此动作监督和餐段监督必须使用不同 head、不同有效标签 mask。

当前 FD-I 源域路线是右腕、5s 窗、64→25Hz、16D unit-free 表示，固定 27 人训练/7 人验证；每人每类最多 256 个离散窗，并非利用了全部连续记录。原始 start sample 可定位时间，但稀疏采样窗不得直接拼成连续序列。

首版沿用 source manifest 中的 27/7 身份划分和既有冻结 checkpoint（SHA256 `c6276837b1366117075e7e8a7504e084926cbfc5d80b98b863e442255995efc4`）。源域验证人不参与拟合、早停或配置选择；左右腕按同一受试者归组，不算独立人。新增数据启用前必须审计跨子集身份与目标受试者重叠。

物理单位仍未得到可靠确认。unit-free 预处理抑制单位差异，但会损失幅值和重力姿态信息；不得宣称已解决所有域差异。左右腕镜像、饮水类别和新归一化都作为独立后续因素，不能随架构更换一起加入。

官方数据页目前为 v1.1，本地目录标为 v1.0；不得静默替换文件。官方许可为 CC BY-NC-ND 4.0，竞赛允许外部数据不等于消除了许可限制。研究使用及后续权重分发需分别确认，不将 FD 原始数据打进 dist。

来源：[KU Leuven 数据集官方页](https://rdr.kuleuven.be/dataset.xhtml?persistentId=doi:10.48804/CN8VBB)。

## 4. 模型数据流与职责

```text
全部允许使用的连续 session IMU（保留时间与缺口）
  → 5s 局部动作 encoder → 16D tokens
  → 连续时间 Transformer
      ├─ dense mealness / boundary head → 新候选
      └─ 候选内部序列 + 独立外围上下文 → event verifier
旧候选 ∪ 新候选 → 固定来源信息与去重协议 → verifier → 最终事件
```

### 4.1 局部输入合同

初版使用当前 FD encoder，不重新训练局部表示。token 基础步长 5s，保留 sid、起止时间、有效覆盖、缺失 mask 和 encoder 身份。不能只对旧候选附近产生 token：定位路径必须覆盖全部允许的有效时段。

不跨 sid 或真实采集缺口拼接，不用插值伪造长段连续数据。相对时间编码使用实际秒数，不把数组下标当物理时间。未知标签时段不自动标负。

### 4.2 层级时间建模

初版推荐 token projection 到 64D，2 层 pre-LN Transformer、4 heads、FFN 128D、dropout .1。先用一个固定小架构检验假设，不搜索多个宽度、层数、预训练模型。

定位路径采用 30min 上下文块、15min 输出责任区；块之间的重叠只提供上下文，每个有效 token 只能有一个输出所有者。session 首尾按有效长度处理，不把 padding 当数据。实现计划必须给出边缘责任区及缺口的确定性算法与测试。

候选复核保留候选全长：超过单块长度时分块编码再做 masked chunk pooling，不能中心裁剪丢掉餐段。候选内证据与外围背景分别聚合再融合，防止长背景直接淹没短餐的局部动作。外围上下文初版固定前后各 10min，裁到 session 边界。

新路径不加入绝对时钟/受试者身份捷径。既有对照已有的特征保持原样，并单独披露；不能宣称整个 incumbent 没有时间先验。

### 4.3 双任务监督

定位 head 的 mealness 与边界监督只来自目标训练受试者的真实餐段标注；按 token 与 GT 的时间交叠定义软占用标签，边界标签与有效覆盖 mask 在实施计划中冻结。

FD 手势监督用于动作结构学习，不能代替目标 mealness。若以后取得可验证的 FD 餐段标注，须另行登记标签版本、来源、覆盖与使用方式，不能用最长手势间隔之类启发式构造“真值”。

候选 verifier 使用目标训练分区中的固定匹配标签，区分正例、负例及按既有合同处理的歧义例。label/IoU 匹配规则首版沿用项目合同，不为提高新模型成绩修改评价定义。

## 5. 分阶段验证：分开回答三个问题

### T0 — 数据与运行合同

只构建身份/标注/覆盖/时间轴审计、配置与测试，不训练。统计连续序列可用长度、动作类别覆盖、缺口、候选长度分布和真实内存需求。pickle 整体反序列化与实际训练参与身份须分别披露，不能把未用于拟合说成完全未读取字节。

### T1 — 现有候选的时序复核

保持旧 proposal、局部 FD encoder、训练样本和评价协议不变，比较：

1. 既有 incumbent 对照；
2. 同一 token 的 mean/std pooling + 简单读出；
3. 同一 token 的小 TCN 时序读出；
4. 固定 Transformer 候选复核。

2/3/4 使用相同的候选内部/外围输入范围与监督，避免把更丰富的输入冒充 attention 收益。参数量与耗时报告而不强行相等。训练目标是最终 TP/FP 的可用权衡，不把 AP 单独当最终成功。

### FS1 — 可选、独立的 FD 连续序列扩充

阶段全名为 **FD-sequence-1**。只有 T0 证明数据合同可用，且 T1 的管线验证正确后，才单独注册本阶段配置。

与对应 T1 模型保持架构和目标训练不变，只改变是否加入 FD-I source-train 连续序列动作辅助训练。抽样保留真实相邻窗口和时间间隔，覆盖不同日常活动；不能只从旧稀疏 token bank 拼接。限定每人/每时段采样预算，报告实际独立小时数，避免海量重叠窗口造成“样本扩充”假象。

初版延续 eating-vs-other、排除饮水与模糊窗的源域标签合同；引入饮水三分类或左腕是后续单因素实验。辅助动作 head 接在时序 encoder 后，而不是只训练一个与时间模型无关的 token 分类器。

冻结已有 FD encoder 时，新增源域训练只更新时间模块；若解冻局部 encoder，必须进入 T3。目标餐段 loss 和 FD 手势 loss 分头计算；混合比例、loss 权重和 optimizer steps 在看结果前锁定。

### T2 — 全天定位与候选联合

先单独检查 dense head 生成候选的覆盖/重复/FP 成本，再按预注册规则合并旧候选，接固定候选复核路径。记录新增可达 GT、短餐覆盖和新增最终 FP，不能只展示候选 recall。

允许 T1 复核没有增益但管线正确时，独立验证定位假设；T1 失败不等于“漏候选”问题不存在。不过不能靠自动扩大 Transformer 或不断重调 decoder 绕过失败。若 T1 新 verifier 无效，T2 必须预先固定使用 incumbent 或明确的已验证复核对照，禁止看结果后挑组合。

proposal 阈值、边界合并、来源去重、cap、最低长度处理均在 inner protocol 内冻结。不得用固定长餐门槛直接删短餐；任何改动都需记录短餐召回代价。

### T3 — 条件联合微调

只有前述模块出现可复现信号才另行注册：小学习率解冻局部 encoder，联合定位与复核，必要时保留 FD 动作辅助 loss。不同层学习率、冻结范围与任务权重在训练前固定。不把模型更大当成下一阶段的自动理由。

## 6. 受试者隔离与预测生产合同

初始开发只使用原 T24；V7、outer raw/labels 不进入训练、采样、归一化拟合、预训练、阈值选择或早停。T24 已重复用于开发，重新分折不等于独立测试。

目标训练、监督适配、source+target 联合训练均在每个 inner-train 中独立执行。用于 inner-val 的任何 learned representation 不得见过该人的 raw。纯 source-only、已证明无目标重叠的冻结 checkpoint 可共享。

归一化、PCA、校准器、融合器及 event policy 只在当前允许的训练分区拟合。目标 producer 的概率、dense proposal 或 embedding 若作为下游训练输入，必须来自相应 subject-held-out producer；不能用训练内高质量输出训练 verifier，再用 OOF 输出测试。

不同 head 共享 encoder 时，必须审计梯度与标签接触边界。最终 wrapper refit 只能在内层选择全部冻结后使用 wrapper-train；health 分区仅推理。所有身份集合、checkpoint、配置与输出保留 hash。

## 7. 评价与进入 outer 的条件

主指标：相同 GT、相同事件匹配合同下的 aggregate event F1，并同时报告 TP/FP/FN、PPV、recall、短餐 recall、候选 recall，以及按受试者 F1 的 median/IQR/P10、改善/恶化人数和无 GT 个体的 FP。

补充：逐折方向、分数校准、拒绝真例/最终 FP 的变化、参数量、显存、训练时间与推理吞吐。不能要求所有指标同时提高，也不能只挑一个有利指标掩盖主指标下降。

源域 AP 改善不作为终点。T24 inner 有实际收益才值得申请独立验证；参考工程门槛为相对配对 incumbent **至少 +0.01 aggregate F1，且多数 wrapper 非下降**。划分、臂数和门槛必须在新结果之前写入实施计划并提交，不事后降低；若未达门槛，记录探索信号而不自动调用 outer。

新完整 outer evaluation 需单独审批并锁定协议；反复使用的 outer 只能作为 development evidence。最终正式改善超过 .03 时提交用户审批，批准且完成部署验证后才更新 dist；不自动发布模型。

## 8. 效率、失败与停止边界

实施计划必须先列出各阶段拟合次数（包括 OOF/refit）、固定 optimizer steps、batch/token 数、每臂时间上限和总 GPU-hours。不能把数个 wrapper 的预算只按一个模型估算。第一轮每阶段只允许一套预注册结构；硬件充足不代表允许无限搜索。

优先 CUDA 批处理与 masked token batching；CPU 使用有界线程，避免多层并行过订阅。混合精度需验证损失/分数数值稳定性；CPU/GPU embedding 与 score 按容差检查，阈值邻域单独记录，不强求浮点边界事件完全一致。

冻结 encoder 的 token 可复用，但缓存必须包括数据/预处理/encoder hash、时间索引与拟合主体身份；目标适配后的表示不能跨 fold 复用。首轮持久派生缓存上限 **2GiB**，达到上限停止新增或删除可重建的失败缓存，不删除原始数据与不可替代证据。

任何身份冲突、标签来源不明、无效时间被当负例、缺口被拼接、OOF 生产者越界、非有限 loss 或缓存身份不一致，都停止并报告；不改划分/标签/预算来绕过错误。OOM 可降低执行 microbatch 并保持有效 batch 与更新数不变，记录修复，不静默改科学配置。
