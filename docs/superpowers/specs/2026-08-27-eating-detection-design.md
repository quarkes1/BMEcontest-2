# 基于智能手表传感器的进食检测算法 — 设计文档（Spec）

> 状态：已获用户批准（2026-08-27）。本文档是后续实施计划的依据，实施计划随文档一起流转。

## 1. 背景与目标

- **竞赛**：第十一届全国大学生生物医学工程创新设计竞赛 · 智能穿戴与运动健康赛道 · 赛题二《基于智能手表传感器的进食检测算法》
- **任务**：从智能手表 IMU（加速度计+陀螺仪，~105Hz）+ PPG（44 通道多波长，占空比采样 ~24 行/s）检测进食事件；两种佩戴场景需分别设计算法（惯用手：IMU 动作；非惯用手：PPG 生理信号）
- **评估**：事件 IoU>0.25 判正确 → F1 主指标；正确事件起止时间 MAE 次指标
- **目标 1（算法）**：准确检测进食事件，且算法**轻量化到可部署于智能手表**（这是"先进性和创新性"40 分的核心叙事）
- **目标 2（可视化）**：跨平台网页应用（FastAPI 后端 + 原生 JS + Three.js），展示检测结果时间线 + 手腕姿态角（Pitch/Roll 绝对、Yaw 相对——无磁力计）+ 前臂虚拟骨骼 3D 渲染
- **交付物**：① 打包可执行文件（对测试集生成预测；测试接口文档未发布，预留 I/O 适配层）② 训练源代码 + 复现 README ③ 总结报告（总 ≤12 页）④ 答辩 PPT
- **时间线**：~4 周（2026-08-27 起），预留 9/24-30 组委会反馈窗口

## 3. 架构：四级级联轻量化流水线

```
传感器流 ──► L1 事件唤醒层 ──► L2 场景门控层 ──┬─► L3a 动作专家网络（惯用手, IMU）
   (105Hz IMU     双通道：IMU活动唤醒   倾角标准差判惯用/非惯用  │
    + 24行/s PPG)   + 周期PPG巡值          (wearHand 标签监督)    └─► L3b 生理专家网络（非惯用手, PPG）
                                        ──► 动态可靠性加权融合 ──► L4 状态解码与事件输出
                                             alpha=f(PPG SNR, 灌注指数)   HMM + 边界膨胀±6s ──► 事件列表
```

### L1 事件唤醒层（守门员）
- 加速度合值 2s 滑动方差 + 过零率 + 0.5-2Hz 带通能量 → 决策树（max_depth=6，<1KB）
- **双通道**：IMU 活动唤醒（高灵敏度）+ PPG 周期巡值（每 30s、8s 短窗，补非惯用手静态进食）
- 叙事：全天候超低功耗常驻（~10K MACs/s）

### L2 场景门控层（分流器）
- 特征：倾角（重力方向与腕 Z 轴夹角）均值/标准差、姿态角变化率分位数
- 轻量分类器（逻辑回归/GMM），scene 真值监督；部署时自包含；低置信走 IMU 保守分支

### L3a 动作专家网络（惯用手分支）
- 输入：5s×105Hz 窗口，11 通道 = 重力分离线加速度(3) + 陀螺(3) + **0.5-2Hz 带通显式通道(3)** + 合值(1) + 带通能量包络(1)
- 结构：1×1 stem → 3× 深度可分离卷积块（32→64→128，stride 2）→ GAP → FC64 → 双头：进食概率（BCE）+ **餐具 7 类多任务辅助头**（推理丢弃）
- 约束：≤300K 参数、≤50M MACs/窗；预处理**不做平滑**（文献有害）、镜像增强、重力分离、标准化
- 物理锚点：0.5-2Hz 咀嚼震颤（显式通道）、手口抬举路径（线加速度积分）

### L3b 生理专家网络（非惯用手分支）
- 输入：30s 窗（步长 10s）PPG 44 通道 + 弱 IMU 姿态
- 特征：**多波长噪声抵消**（通道相关性分离运动伪影，华为 EP4186416 思路）→ PPG 波形嵌入（3 层 Conv → 64 维）+ HR/RR 间期/RMSSD/LF-HF（分钟级低噪声段）/灌注指数 AC/DC/SNR
- 模型：GRU(72→96) + MLP → 概率；~150K 参数
- 物理锚点：交感激活/迷走撤离（Niizeki 2016 RR 间期缩短；Lu et al. LF/HF↑≥60min；Verrier 2025 腕部 PPG 波形含进食信息）

### 动态可靠性加权融合层
- alpha = sigmoid(MLP(PPG_SNR, 灌注指数, IMU 活动度))，30s EMA 平滑；融合分 = alpha·P_ppg + (1-alpha)·P_imu
- 对照实验：可学习 2 层 MLP 融合 vs 手工 alpha 公式

### L4 状态解码与事件输出
- 2 态 HMM：发射 = 校准后融合分；转移自环 0.98/0.995；Viterbi 全会话解码
- 事件后处理：合并间隔 <30s；过滤持续 <45s；**边界膨胀 ±6s**（IoU>0.25 下收益、MAE 代价 ≤8s）
- 输出：`[{start_ms, end_ms}]`

## 4. 训练与评估

- 窗口标签：与事件 IoU≥0.5 正、=0 负、灰区丢弃（训练）；推理连续打分不二分类
- 负采样：会话内分段 3:1 负正比 + WeightedRandomSampler；正样本全保留
- 划分：按受试者 GroupKFold 5 折（45 人 → 每组 9 人），两场景均衡，seed=42，manifest 落盘
- 增强：左右镜像（X 翻转，wearHand↔dietaryHand 标签同步映射）、幅度抖动 ±10%、时间伸缩 ±5%、通道 dropout
- 评估：`src/eval/metrics.py` — IoU>0.25 事件匹配（匈牙利一对一）→ F1/灵敏度/PPV + 匹配事件起止 MAE；两场景分开 + 总体
- **LightGBM 基线**：同窗口手工特征，对照实验（报告"轻量基线 vs 深度学习"）
- 硬件：RTX 5060 Laptop 8GB → fp16 AMP + batch 128（L3a）/64（L3b）
- 预警线：9/9 前任意折 F1>0.7；9/16 前 5 折均值定型

## 5. 可执行文件（提交物①）

- PyInstaller 单文件 + **ONNX Runtime** 后端（L3a/L3b 导出 ONNX；L1/L2/L4 纯 numpy）→ ~80MB、无 torch
- CLI：`bme_predict.exe <测试数据目录> [--out predict.csv] [--config adapter.json]`
- **`src/infer/io_adapter.py` 适配层**：规范中间格式 CanonicalSession 与外部格式解耦；接口文档发布后只改此处
- 输出 predict.csv 列名占位 `externalid,startTime,endTime`（毫秒），随文档调整；容错：单会话失败不中断、写 predict.log

## 6. Web 应用（目标 2）

- FastAPI + 原生 JS + Three.js（CDN），零构建链
- 路由：会话列表/元数据+事件/姿态(10Hz)/降采样 IMU/PPG/SNR 轨迹
- 三级缓存：姿态角 10Hz 全量缓存（~1.2GB）+ 事件 JSON + LRU 内存；原始 TSV 流式按需读
- 前端：时间线（真值 vs 预测三色，拖拽缩放）↔ 姿态曲线（Pitch/Roll/Yaw，Yaw 标注"相对"）↔ Three.js 前臂骨骼（肩→肘→腕→手，腕四元数驱动，肘由前臂方向反推，身高比例定骨长）
- 预选 4-6 个高光会话预生成缓存，答辩零等待
- 姿态解算：低通重力分离（fc 0.8Hz）+ 互补滤波（kp 0.3/ki 0.01，静止段零偏校正）；相对 Yaw（首个静止段归零）
