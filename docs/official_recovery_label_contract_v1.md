# 跨文件餐次标签修正：固定训练侧窗口对照

2026-10-19，基于已批准的召回恢复计划自主执行。

## 依据和假设

历史宏窗脚本及micro_cache.meals_by_session只向会话传递完全包含的整餐标注。完整餐段跨会话时，其局部窗口可能被标成负类。这不是官方测试逐餐归因；隐藏测试仍只有42TP/26FP/70FN。

仅读既有39主体验证缓存的初查中，按完整餐次重叠可发现7091个宏窗、16516个微窗从旧负类变为正类，涉及32人。此观察只支持修正标签合同的配对实验，不代表事件模型已改善。

## 固定比较

- 仅使用既有A6 manifest的T24及三个16train/8health划分；V7及outer主体不参与拟合、选取阈值或评分。元数据和共享NPZ可能物理解压其他主体，立即按身份裁剪；不宣称文件字节从未读取。
- A：既有缓存标签；B：同一窗口特征与时间轴，根据所属受试者全部有效餐次重算标签，不要求整餐包含在该文件。
- 宏窗正类沿用重叠>50%；微窗沿用重叠>=50%；完全不重叠且距餐>=300秒才为负，其余灰区不训练、不进入窗口分类指标。
- macro 63D / HGB150轮、micro47D / LGBM300树均复用现有工厂和参数，seed20260908。固定每会话负样本最多3倍正样本，最低保留1个，seed20260901；不调整网络、阈值、重采样比例或负样本规则。
- 两臂在各自训练标签上抽样，差异属于标签合同的后果，不能称为固定训练样本量的纯模型消融。逐折记录训练窗口数及标签迁移。
- 每个health分支的评价目标统一为完整标签B；不以A旧标签评价A而以B新标签评价B。无候选餐不从后续事件分母删除。
- 所有imputer和模型只fit当前16人。先完成全部6个分支/12次窗口模型fit，再统一汇总三折AP、BCE、ROC AUC与固定阈值召回；窗口指标不是事件F1。
- 保存每个health窗口的配对评分、窗口身份、原/新标签、输入哈希和训练主体，禁止回选参数。无early stopping、无seed搜索、不运行outer、不改dist。

## 判读及下一步

首先验证修正逻辑、跨主体隔离和不改变原缓存。若任一尺度的三折平均AP至少提高.02且至少2/3折提高，支持进入新的完整标签nested事件对照；否则保留标签缺陷事实，分析为何未转为窗口增益，不凭正确的标签逻辑宣称性能提升。

下一阶段必须重新在每个verifier/policy训练分区内部拟合窗口生产器。不能直接把本次三折OOF的其他折分数拼入meta训练，因为那些模型可能见过当前health受试者。

## 资源与保护

CPU最多8个数值线程；无GPU需求、原始信号读取或新特征缓存。目标墙钟<=30分钟、输出<=64MiB、磁盘剩余至少10GiB；只保存分数和紧凑诊断，不保存两臂训练模型。正式release/model/submission EXE输入输出哈希不变。运行异常标INCOMPLETE，已完成折不挑选成成功结果。
