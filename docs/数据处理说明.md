- HUAWEI Research 平台下载（项目：第十一届…赛题二_训练集），2026-06-20 ~ 2026-08-13
- 原始：1165 会话 / 45 受试者（含 test）/ 100GB TSV；下载 0 失败
- 下载后规范化：GBK→UTF-8、表头提行（原脚本 reverse-sort 致表头乱序）、附件路径与本地目录 1165/1165 校验一致

## 剔除规则（历史数据审计记录）
- 早期数据校验脚本和 `outputs/data_quality.json` 已不再随当前项目发布；以下数字保留为
  已完成的数据审计记录，不能作为当前可执行命令的说明。
- 当前管线直接从原始 `collect_data*.txt` 读取（`src/pipeline/io/raw_session.py`），
  会话缓存与特征缓存的构建入口见根目录 `README.md` §6；历史缓存压缩脚本已随交付清理
  移除（见 `tests/fixtures/deletion_manifest.json`），可从 git 历史检出。
- **test 用户**：2 会话 + 1 无效标签（before==after），全部剔除
- **空 externalid 会话**：2 行（索引 CSV 中受试者 ID 缺失），无法归属受试者，剔除
- **二进制损坏会话**：16 个（1.4%，分布于 11 名受试者），按早期审计规则识别并排除；
  当时生成的黑名单文件已随历史诊断产物清理，不再作为当前发布文件。
- **无效标签**：after<=before 的餐次记录剔除（7 条）
- 数据中的重复行（~5.9%）保留（窗口特征对其不敏感），W2 训练管线再决定去重策略

## 占空比采样（重要语义）
- 历史记录称PPG约78%行为全零且有效约24行/s；不能据此断言所有零值均属调度而非缺失。
- 2026-10-13 T24固定抽样发现约602ms一个PPG时间戳，每完整包15行且向量均不同；仅前20列活跃。
  因而旧“44通道窗口等效~1kHz”和README旧“有效采样~2Hz”均不能作为波形采样依据。
  约25Hz/列的包内序列是待核实假设；波长/列定义、时序及时间戳锚点尚未确认，不能直接计算HRV。
  详见[探查报告](../outputs/challenger_70/representation_v2/hand_ppg_audit/report.md)，抽样不代表全数据质量。
- 下载附件及组内代码的进一步核查见[PPG字段与下载解析证据](PPG字段与下载解析证据.md)：
  下载器未定义波形列；BME-CONTEST明确使用PPG3/PPG5作为绿光、25Hz处理，但原始映射依据仍待补充。
- ACC/GYRO ~7.3% 行全零：同理
- loader.py 输出 imu_valid/ppg_valid 掩码；无效行时间戳置 -1

## 时间网格与窗口
- 行空间即时间网格：IMU 行率 ~105Hz（实测中位 105.9-113 行/s）；会话级 row_rate 记录于 meta
- 窗口：5s=525 行，步长 1s=105 行；L3b 计划 30s 窗/10s 步长
- 标签：窗口与任一餐的**重叠占窗口时长比例 ≥0.5 → 正**；零重叠 → 负；其余灰区丢弃（训练）
- ⚠️ 注意：事件级 IoU 规则在此不适用（5s 窗口 vs ~15min 事件 IoU 恒 <0.01，实测曾导致全缓存仅 34 个正样本，已修复）
- 灰区窗口在特征缓存中 y=-1

## 场景定义
- 惯用手场景 dominant：wearHand == dietaryHand（~112 餐）
- 非惯用手场景 nondominant：wearHand != dietaryHand（~176 餐）

## 划分
- 按受试者 GroupKFold 5 折（45 受试者，每折 ~9 人），seed=42，manifest 落盘 cache/splits/fold{k}.json

## 低行率会话（补充）
- 3 个会话 row_rate < 4（fs=0.5/1.9/3.9，长空档型：如 11h 会话仅 ~17 分钟有效数据）
- 处理：带通特征在 fs<=4 时降级为零（window_features 内置防护，推理管线同样适用），不崩溃不丢弃
- 依据：用户明确要求测试集可能含异常数据，管线必须容错
