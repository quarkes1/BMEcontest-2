## 1. 背景与决策

### 1.1 赛事评估规则（锁定，以 Resources/试题.txt 为准）

- **事件级（Episode-level）评估**，非窗口级、非受试者聚合：
  - 对每个预测 Episode 与 GT Episode 计算 `IoU = Intersection / Union`
  - `IoU ≥ 0.25` → 正确检测（TP），全局贪心一对一匹配
  - 灵敏度 = TP / 真实事件数；PPV = TP / 预测事件数；F1 = 2·Sens·PPV/(Sens+PPV)
  - 次要指标：正确匹配事件的起止时间判断误差 MAE
- 两种佩戴场景（试题明确要求分别设计）：
  - **惯用手**：进食手部动作特征明显 → IMU 运动模式分析
  - **非惯用手**：手部动作弱/不可捕捉 → PPG 生理信号（心率变化等）+ 其他特征

### 1.2 关键决策

1. **停止任何窗口级参数微调**——不再做 w/tau/g/p/dil/K 网格调参；参数仅按官方后处理规范固定
2. **评估口径切换**：现有系统按受试者聚合（`compute_metrics_by_subject`），官方为全局事件级。
   实测差异：现有管线全局口径均值 0.280 vs 按受试者口径 0.337——**全局口径才是提交分数**
3. **FD-I/FD-II 已下载**（./FDdatasets），用于 Episode-level 预训练
4. 用户授权：除 /Archieves、/Data 外，直接删除新架构不需要的文件（不打包归档）

## 2. 现状盘点

### 2.1 现有系统（检测即排序）

```
[1s 活动包络 env × 时刻先验] → 提案池（活动+先验两池）
  → LGBM 14 特征排序 ⊕ MM-Ranker 深度分（w 加权）
  → 会话门控（AUC 0.88）→ 阈值选窗 → 事件后处理（merge 120s / min 120s / dilation）
  → 按受试者 F1 评估
```

### 2.2 已知事实（决定方案取舍）

| 事实 | 影响 |
|---|---|
| 全局口径 F1 0.280（现有管线）/ 0.180（官方后处理无膨胀） | 官方后处理必须保留边界膨胀组件或等效手段 |
| dilation 60-120s 是 TP 最大贡献者（fold0 raw 10→13 TP） | 官方流程（平滑/融合/过滤）应叠加 dilation 对照 |
| 180s 融合会吞并相邻真餐（fold2 TP 8→5） | 融合参数需在官方值上验证事件间隔分布 |
| gyro 4-16Hz 高频能量：受试者内餐窗判别 0.61-0.62（双折一致） | 惯用手分支 Bite 触发器的信号依据 |
| PPG 分支此前负向（块统计噪声）；MA 掩码可用 | 非惯用手分支需 HR/HRV 慢响应特征重构（3min 块）而非旧 5s 块 |
| MO bite 预训练无事件级增益；zcr/多频带无转化 | FD 预训练重点在 Episode-level 任务对齐，不做 bite 级迁移 |

## 3. 三阶段设计

### 阶段一：官方评估指标与 IoU 后处理模块重构（Metric Alignment）

**目标**：官方口径评估函数 + 官方后处理流水线，产出 5 折对比表（形态学前/后）。

**模块**：`scripts/official_iou_eval.py`（复用 `rank_events_v2.prepare_fold` 打分，禁止复刻）

```
official_iou_eval.py
├── official_metrics(preds, gts)      # 全局 IoU≥0.25 贪心匹配 → sens/ppv/f1/mae
├── map_to_1hz_timeseries(cands, fuse)  # 候选概率 → 1Hz 全天连续时间轴（重叠窗取 max）
├── smooth_series(series, t0, win_s=60) # 连续序列 60s 高斯/移动平均平滑
├── threshold_episodes(series, t0, tau) # 阈值截断生成 Episode
├── fuse_events(evs, gap_s=180)       # Episode Fusion：间隔<180s 合并
├── min_dur_filter(evs, min_s=120)    # 过滤 <120s 孤立框
├── decode_official(row, cfg, post, dilate_s)  # 完整官方 Pipeline
└── run_fold(k, cfg, ...)             # 官方 vs 现有管线对比
```

**平滑对象（用户审阅修正 v1.1）**：平滑**必须作用在连续时间轴的秒级概率序列**
（Continuous Probability Time-series），而非离散候选窗——离散候选是长度不一的区间，
直接高斯平滑会导致重叠窗概率冲突。

**官方 Pipeline 顺序（锁定）**：
```
候选预测概率 → 映射回 1Hz 全天连续时间轴（重叠窗取 max/加权）
→ 60s 高斯/移动平均平滑 → 阈值截断生成 Episode
→ 180s 连通域合并 → 120s 最小时长过滤 →（可选）边界膨胀
```

**rank_events_v2.py 重构**：main 的加载/打分段抽为 `prepare_fold(k, prior_grid, norm_score)`，
official_iou_eval 与 main 共用同一函数（消除复刻泄漏风险，E-20260831-01 教训）。

**验证矩阵**（5 折 best 配置，全局口径）：

| 列 | 含义 |
|---|---|
| 原始选窗 | 无任何后处理（阈值选窗直出） |
| 官方后处理（无膨胀） | 1Hz 映射 + 60s 平滑 + 阈值 + 180s 融合 + 120s 过滤 |
| 官方后处理 + dilation | 上述 + 边界膨胀（对照，保 TP 组件） |
| 现有管线 | merge 120s + min 120s + dilation 60/120s |

**验收**：对比表打印完成，确认各组件贡献符号；将 dilation 与融合参数的最终选择写入
本设计文档（实现/修改同步更新）。

**M1 结果（2026-09-01，5 折 best 配置，全局官方口径）**：

| 变体 | F1 | Sens | PPV | MAE |
|---|---|---|---|---|
| 原始选窗（形态学前） | 0.209 | 0.200 | 0.229 | 454s |
| 官方 v1.1 后处理（60s 平滑+180s 融合+120s 过滤） | 0.168 | 0.152 | 0.195 | 552s |
| 官方 v1.1 + 60s 边界膨胀 | 0.181 | 0.163 | 0.211 | 599s |
| 现有管线（merge 120s + min 120s + dilation） | **0.280** | 0.315 | 0.258 | 447s |

解读：①官方口径（全局事件聚合）下现有管线 0.280——此前 0.337 是按受试者口径，
**提交口径以全局为准**；②官方后处理（1Hz 平滑+阈值截断）边界漂移（fold0 TP 10→5，
MAE 454→552s），低于候选级选窗——参数按官方锁定不改，阶段三模型改进在官方
Pipeline 下评估；③dilation 对照仅 +0.013 且 MAE 恶化，不纳入官方流程。

### 阶段二：FD-I/FD-II 预训练接入（Pre-training Hook）

**目标**：FD 数据 → Episode-level 预训练 S1 TCN 排序头 + S2 门控 → checkpoints/fd_pretrained_s1.pt

**数据预处理**（`scripts/prep_fd.py`）：
1. 盘点 ./FDdatasets 结构（IMU/PPG 格式、采样率、标签粒度——确认是否为 Episode/meal 级）
2. **通道映射校验（用户审阅修正 v1.1）**：FD 原始文献采样率（IMU 50/100Hz，PPG 50Hz）
   与通道命名/轴向可能与 HUAWEI 平台不一致。先提取 1-2 个 session：
   - 核对通道顺序（acc x/y/z、gyro x/y/z、PPG 通道数）与轴向
   - 计算合幅值（Magnitude）与 PSD（功率谱密度）
   - 确认重采样到 10Hz（IMU）与 5s 块（PPG）后，特征分布（Mean/Std/Mag）
     与目标数据集同数量级——**通过校验后才启动全量预训练**
3. 按现有 L1 缓存格式生成块统计特征 + MA 置信度掩码

**预训练任务**（`scripts/pretrain_fd.py`）：
- 任务 = Episode-level 候选分类（与 MM-Ranker 相同任务头，而非 bite 级——MO 教训：
  bite 级预训练不迁移到餐次级）
- 输入复用 MMRanker 结构（n_imu=6 或 7 视阶段三），训练 Focal + 硬负样本（同 train_ranker）
- 保存 `checkpoints/fd_pretrained_s1.pt`（encoder = imu_in + tcn）

**M2 通道校验结果（2026-09-01，设计文档 v1.1 修正②落地）**：
- FD 数据实测：Shimmer3 @64Hz，6ch [ax,ay,az,gx,gy,gz]，acc 合幅值 mean ≈9.86（**m/s²
  物理单位**），gyro mean ≈29.8（deg/s）
- 目标数据集实测：acc 合幅值 mean ≈3797（**raw ADC 未校准单位**），gyro ≈141.6——
  **acc 尺度差 ~385 倍**，直接喂预训练必失效
- **归一化方案（新增）**：预训练与微调统一用 z-score（统计量从 FD-I 全量训练集
  6 通道计算 mean/std，存 checkpoint meta；本项目输入用同一统计量归一化）
- FD 标签语义（新增）：FD-I 全天干净标注（0=确认非餐 → 负样本来源）；FD-II 仅餐
  时段标注（0=未标注，**不可作负样本**）；正样本 = 两数据集 eating 手势时段
- Episode 推导：bite=1 连续簇，簇间 gap<180s 合并，边界 ±60s 膨胀

**验收**：FD val 折 AUC；权重文件产出（含归一化统计量）。

### 阶段三：惯用手/非惯用手双分支架构落盘与提交准备

**目标**：双分支路由 + FD 预训练微调 + 自动验证对比表。

**分支路由**（`src/models/dualbranch.py`）：

```
IMU 4-16Hz 高频能量包络 → Bite 触发器（惯用手分支）→ 拉高 Proposal 召回
PPG 3min 块 HR/HRV 慢响应 + SQI 掩码（非惯用手分支）→ 上下文概率判断
两分支分数 → 自适应信号置信度路由 → Episode 解码
```

- **自适应信号置信度路由（用户审阅修正 v1.1）**：测试集元数据**不能假定提供
  dominant_hand 标记**（静态分支路由会导致推断崩溃）。改为数据驱动：
  ```
  计算当前 Session IMU 4-16Hz 平均能量分布
  ├─ 检测到显著手-口动作峰值（Bite Feature 丰富）→ 提升惯用手分支（Bite Trigger）权重
  └─ IMU 动作极平缓但存在进食概率 → 自适应切向 PPG 慢响应（HR/HRV + SQI 掩码）分支
  ```
  路由权重 = 按会话级 4-16Hz 能量统计量（均值/峰值占比）连续插值，非硬切换
- 惯用手分支：保留 IMU 4-16Hz 高频能量通道（已在 build_candidate_windows 实现为第 7 通道，
  7ch 缓存 fold0 已重建验证——此前单折负向，将结合 FD 预训练复测）
- 非惯用手分支：PPG 5s 块统计 → **3min 块 HR/HRV 慢响应特征**（新实现，替代旧 5s 块——
  旧块统计噪声大且负向；慢响应块 + SQI 掩码是试题指定的非惯用手信号）
- 微调：加载 FD 预训练权重，冻结 TCN 前半（imu_in + 前 3 层 TCNBlock），微调后半 + 融合头

**自动验证**：`official_iou_eval.py` 5 折重跑，输出形态学前/后 × FD 预训练前/后 2×2 对比表。
